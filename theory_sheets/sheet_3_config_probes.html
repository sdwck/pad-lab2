1. Разделение конфигурации: ConfigMap vs Secret

Соответствует III фактору 12-Factor App: конфигурация строго отделена от исполняемого кода.

ConfigMap (pad-config)
  • Хранит несекретные переменные окружения.
  • В проекте: URLs внутренних сервисов (CATALOG_URL: http://catalog-service:8002), REDIS_URL, LOG_LEVEL: INFO, ENVIRONMENT: kubernetes.
  • Инжектируется через configMapKeyRef или envFrom.
Secret (pad-secrets)
  • Хранит конфиденциальные ключи и токены.
  • В проекте: JWT_SECRET, PAYMENT_GATEWAY_KEY, ADMIN_TOKEN.
  • Значения кодируются в Base64.
  • Разграничение доступа через RBAC, сокрытие в логах, шифрование в etcd at rest.

2. Проверки здоровья: LivenessProbe vs ReadinessProbe

LivenessProbe (Жизнеспособность)
  • Вопрос: Контейнер работает или завис (Deadlock, утечка памяти)?
  • Реакция при падении: Kubelet принудительно убивает контейнер (SIGKILL) и перезапускает его.
  • В проекте: httpGet /health, timeout 3s, failureThreshold 3.
ReadinessProbe (Готовность к трафику)
  • Вопрос: Готов ли контейнер принимать трафик прямо сейчас?
  • Реакция при падении: Контейнер не перезапускается. Его IP исключается из Endpoints сервиса, трафик временно не идет.
  • В проекте: httpGet /health, timeout 3s, period 10s.

3. Управление ресурсами: Requests vs Limits

ПараметрНазначениеПоведение при превышении
Requests
cpu: 50m
memory: 64Mi		 Гарантированный минимум ресурсов. Планировщик (kube-scheduler) размещает под только на ноду с достаточным объемом свободных requests. Если свободных requests нет на нодах кластера — под переходит в статус Pending.

cpu: 300m
memory: 256Mi		 Максимальный потолок потребления ресурсов контейнером. CPU: процесс не убивается, включается CPU Throttling (урезаются такты ядра).
RAM: контейнер немедленно убивается ядром: OOMKilled (Exit Code 137).

4. Постоянство данных: PersistentVolumeClaim (PVC)

  • Поды эфемерны: файловая система контейнера сбрасывается при пересоздании.
  • PVC (pad-data-pvc): запрос на постоянный диск размером 1Gi (режим ReadWriteOnce).
  • Стейтфул-сервисы монтируют том в /data с опцией subPath: <service>, что изолирует данные каждого микросервиса (JSON-файлы каталога, заказов, платежей) внутри одного тома.
