Раздел 1
DOCKER И КОНТЕЙНЕРИЗАЦИЯ

1. В чем разница между Docker и виртуальной машиной (VM)?

Виртуальная машина (VM)
  • Работает поверх гипервизора.
  • Внутри полноценная гостевая ОС со своим ядром, системными службами и драйверами.
  • Высокий оверхед: гигабайты диска и ОЗУ на каждую VM.
  • Холодный старт занимает минуты.
Контейнер Docker
  • Не содержит гостевого ядра, делит общее ядро хоста.
  • Namespaces: изолируют процессы (PID), сеть (NET), файловую систему (MNT), пользователей (USER).
  • Cgroups: жестко ограничивают и учитывают CPU, RAM, I/O.
  • Минимальный оверхед: образ ~130 МБ, старт за доли секунды.

2. Почему выбран базовый образ python:3.12-slim?

  • Полный python:3.12 (~1 ГБ): перегружен компиляторами (gcc), сборочными библиотеками. Долго скачивается, увеличивает поверхность атаки (attack surface).
  • python:3.12-slim (~130 МБ): содержит только минимальный рантайм Python и glibc. Меньше вес, меньше уязвимостей (CVE), быстрый деплой.
  • Почему не Alpine: в Alpine используется musl libc вместо glibc. Из-за этого C-библиотеки Python компилируются при сборке и могут работать нестабильно. Debian-slim гарантирует нативную поддержку предсобранных wheels.

3. Зачем запускать приложение не от root (Non-root user)?

  • По умолчанию контейнер выполняется от root (UID 0). При уязвимости побега из контейнера (container breakout) атакующий получает полный контроль над хостом.
  • Решение: создание системного пользователя appuser (UID 10001) и вызов инструкции USER appuser. Приложение работает без root-прав.

4. Порядок инструкций и кэширование слоев в Dockerfile

✗ Неправильный порядок
COPY . .
RUN pip install -r requirements.txt

Любая правка строчки кода сбрасывает кэш. pip install запускается заново при каждом билде.

✓ Правильный порядок (в проекте)
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .

Зависимости меняются редко. Слой с установленными пакетами берется из кэша. Билд занимает секунды.

5. Зачем нужен .dockerignore и почему секреты нельзя зашивать в образ?

  • .dockerignore: исключает из контекста сборки .git/, .venv/, __pycache__/, *.log, тесты и локальные файлы данных. Ускоряет билд, снижает размер образа.
  • Секреты: пароли и токены нельзя передавать через ENV/ARG в Dockerfile, так как они навсегда остаются в метаданных слоев (docker history). Секреты передаются исключительно в рантайме.
  • Docker Compose: декларативный запуск мультиконтейнерного стека (14 сервисов, общая сеть bridge, тома данных, зависимости depends_on).
