1. Чем Docker отличается от виртуальной машины (VM)?

Виртуальная машина (VM)
  • Работает через гипервизор (Type 1 / Type 2).
  • Внутри полноценная гостевая ОС (Guest OS) со своим ядром, демонами и драйверами.
  • Высокий оверхед: гигабайты ОЗУ и диска на каждую VM.
  • Холодный запуск: от десятков секунд до минут.
Контейнер Docker
  • Не содержит гостевого ядра. Все контейнеры делят одно общее ядро хоста (Host Kernel).
  • Namespaces: изолируют PID, NET, MNT, IPC, UTS, USER.
  • Cgroups (Control Groups): жестко лимитируют ресурсы (CPU, RAM, I/O).
  • Минимальный оверхед: образ ~130 МБ, запуск за миллисекунды.

2. Выбор базового образа: почему python:3.12-slim?

  • Полный python:3.12 (~1 ГБ): перегружен компиляторами (gcc), отладочными пакетами. Долго скачивается, увеличивает поверхность атаки (Attack Surface).
  • python:3.12-slim (~130 МБ): только минимальный рантайм Python и glibc. Меньше вес, меньше уязвимостей (CVE), быстрый деплой.
  • Почему не Alpine? В Alpine используется musl libc вместо glibc. Из-за этого C-библиотеки Python компилируются при сборке и могут работать медленнее. Debian-slim гарантирует нативную поддержку предсобранных manylinux wheels.

3. Принцип наименьших привилегий (Non-root user)

  • По умолчанию Docker выполняет всё из-под root (UID 0). При побеге из контейнера (container breakout) атакующий получает полный контроль над хостом.
  • Решение в проекте: создание системной группы и пользователя appuser (UID 10001) и директива USER appuser. Приложение работает без root-прав.

4. Послойное кэширование при сборке (Layer Caching)

✗ Неправильный порядок
COPY . .
RUN pip install -r requirements.txt

Любая правка 1 строки кода сбрасывает кэш. pip install запускается заново при каждом билде.

✓ Правильный порядок (в проекте)
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .

Зависимости меняются редко. Слой с пакетами всегда берется из кэша. Билд длится 2 секунды.

5. Исключения .dockerignore и Секреты в образах

  • .dockerignore: исключает из контекста сборки .git/, .venv/, __pycache__/, *.log, тесты и локальные JSON-файлы данных. Ускоряет отправку контекста демону.
  • Секреты: токены и пароли запрещено зашивать в Dockerfile через ENV/ARG, так как они навсегда остаются в метаданных слоев (docker history). Секреты передаются исключительно в рантайме.
  • Docker Compose: декларативный запуск мультиконтейнерного стека (14 сервисов, единая сеть bridge, тома pad_data для БД, зависимости depends_on).
