Раздел 2
АРХИТЕКТУРА И СЕТЬ KUBERNETES

1. Зачем нужен Kubernetes, если есть Docker?

Docker запускает контейнеры на одном хосте. Kubernetes оркестрирует распределенный кластер:

  • Self-Healing: автоматический перезапуск упавших контейнеров и перенос на здоровые ноды.
  • Auto-scaling: горизонтальное масштабирование количества реплик по нагрузке.
  • Service Discovery & Load Balancing: стабильный DNS и виртуальный IP с балансировкой трафика.
  • Zero-downtime Rollouts: постепенное обновление версий (RollingUpdate) без остановки системы.

2. Базовые сущности: Pod, Node, Control Plane

  • Pod (Под): минимальная единица развертывания. Группа из 1+ контейнеров, делящих общий сетевой стек (IP, localhost) и тома. Поды эфемерны: их IP меняются при перезапуске.
  • Node (Узел): рабочий сервер кластера (компоненты: kubelet, kube-proxy, CRI runtime).
  • Control Plane:
    • kube-apiserver — центральный REST API кластера, через него общаются все компоненты.
    • etcd — отказоустойчивое key-value хранилище состояния всего кластера.
    • kube-scheduler — выбирает узел для размещения пода с учетом CPU/RAM requests.
    • kube-controller-manager — запускает контроллеры сверки (Node, Deployment, ReplicaSet).

3. Что делает Deployment и ReplicaSet?

  • ReplicaSet: контроллер, гарантирующий, что в кластере запущено ровно заданное число реплик ($N$).
  • Deployment: декларативное описание желаемого состояния приложения над ReplicaSet.
    • Обеспечивает обновление RollingUpdate: создает новый ReplicaSet, поднимает новые поды по одному, дожидается готовности (readinessProbe), затем гасит старые поды.
    • Позволяет выполнить откат версии: kubectl rollout undo.
  • High Availability в проекте: для order-service и catalog-service сразу задано replicas: 2 для исключения единой точки отказа.

4. Kubernetes Service и CoreDNS: почему НЕ localhost?

Почему сервисы не могут обращаться по localhost?
Сетевой стек каждого пода строго изолирован. localhost указывает только на контейнеры внутри этого же пода. Запрос от order-service на http://localhost:8002 вернет ошибку, так как каталог запущен в отдельном поде.

  • Решение: сущность Service предоставляет постоянный виртуальный IP (ClusterIP) и стабильное DNS-имя в кластере (CoreDNS).
  • Вызов внутри кластера: http://catalog-service:8002. Служба kube-proxy перехватывает обращение к ClusterIP и транслирует его на реальные IP-адреса живых подов через iptables/IPVS.
